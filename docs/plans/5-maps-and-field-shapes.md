## Map (was Phase 7)

Proposed 2026-10-17 (Ben): a **Map** tab next to Dashboard showing the operation's current state at a glance: every pivot where it is, its fields' status badges, a popup per pivot with its fields' cards, the usual map controls, and a few optional public layers (radar, observed and forecast rain, drought). It reads the same data as the dashboard, with nothing new stored.

**Decided 2026-10-17 (Ben):** the map is its own tab, and the dashboard keeps its layout. Fields are badges on the pivot, not pie wedges (wedges would suggest where each field is). A collapsible side list of field cards. The public layers may be flaky as long as a failure is caught and reported gently. The soil survey comes into Phase 7 (G); weather zones and a map in the email go to later.

- [x] Moving a pivot (or changing its cell) triggers a backfill and recalculation. *(Shipped in Phase 3: `Pivot#backfill_weather` on a cell change; the balance is recalculated on read.)*

**Fields on the map.** We know where pivots are but not where their fields are (`fields.boundary` exists in §4 but nothing sets it). So the map stays honest: the pivot is drawn to scale, and its fields are shown as badges *on* it rather than as made-up areas.
- The pivot's circle or arc, to scale, outlined and lightly filled with its **most urgent** field's status color (irrigate > caution > ok > full; grey when no field is in season or the pivot has no fields).
- At the center, a screen-sized marker (HTML, not to scale) holding one `StatusBadge` per field in season, in name order, with a "Season ended" or "No crop" chip otherwise. Below a zoom threshold (pivots a few pixels across) it collapses to a single dot in the most urgent color with the field count.
- Pivot names label the outline at closer zooms, as in the picker. *(As built: the marker shows the name from zoom 13, badges from 11.5, a dot below; fields not in season are gray dots.)*
- *Later, not Phase 7:* drawing fields as sectors of their pivot (a start and end bearing per field, set in the picker; most split pivots are halves or quarters). Then each sector takes its own color. Only once growers ask for it.

### E. Optional overlays (all off by default, loaded by the browser, never by our server)
Each overlay lives in a registry (`lib/map/overlays.ts`: id, name, tile URL builder, attribution, legend stops, refresh interval, description), unit tested for its URLs. All of these were checked on 2026-10-17: they answer with CORS headers and serve Web Mercator.

**When a source fails** (decided: depend on them, but fail gently): MapLibre's `error` events are caught per source. The layer stays switched on but is marked "unavailable" in the panel, a small notice shows on the map for a few seconds ("Radar isn't loading right now; try again later"), and the map, pivots and other layers carry on. One notice per layer per page visit, not one per tile. The layer retries at its next refresh, or when it's switched off and on.

### F. Soil survey in setup
USDA NRCS Soil Data Access (SSURGO) has both a map layer and a query API, free and CORS enabled (checked 2026-10-17: a point in the Central Sands returns "Plainfield sand, 0 to 2 percent slopes", Plainfield 90%, surface texture Sand, AWC 0.08).
- [x] **Soil layer** on the pivot picker (and as an overlay on the Map tab): map-unit outlines from the WMS (`SDMDataAccess.sc.egov.usda.gov/Spatial/SDM.wms`, layer `mapunitpoly`), visible from about zoom 13, with each unit's name on click. *(A "Soils" toggle on the picker and a layer on the Map tab. No click-to-identify, as clicks place or select pivots; the survey box lists the map units under the pivot instead.)*
- [x] **Suggest the soil type** for a pivot's fields: query the map units under the pivot's circle or arc (`Tabular/post.rest`, `SDA_Get_Mukey_from_intersection_with_WktWgs84` with the polygon from `pivotRing`). Take each unit's area share and its dominant component's surface texture, and show "Soil survey: mostly Plainfield sand (82%), some Richford loamy sand (18%) → Sand". The field form and quick setup preselect that soil type when the user hasn't chosen one, and never overwrite a choice. The user can always change it. *(`lib/soils.ts`, `SoilSurvey.svelte`: area shares from `mupolygon` intersected with the pivot's polygon in one query, about 5 s. Quick setup's fields and a new field in Setup take the suggestion until the user picks a soil; the pivot form shows it for information.)*
- [x] **Soil types reviewed** (Ben, 2026-10-17): Loamy Sand, Sandy Clay Loam, Silty Clay Loam and Muck added, and sandy loam, loam, silt loam and clay loam updated, from Wisconsin SSURGO medians and Saxton & Rawls (2006). The legacy values had no known source. Each entry in `soil_types.yml` gives both sources' values and the legacy one.
- [x] **Texture mapping** to our eleven soil types, as a table in `lib/soils.ts`, unit tested: each USDA texture to its class, with modifiers dropped (fine sand and coarse sand → Sand, loamy fine sand → Loamy Sand, fine sandy loam → Sandy Loam), muck and mucky peat → Muck, and no suggestion for peat or textures we don't have (silty clay, sandy clay).
- [x] Failure is quiet: no suggestion and a short "Soil survey unavailable" note; setup never waits on it. Outside the survey's coverage (Canada) there's no suggestion.
- [x] **About page:** a Soils section: what the soil type sets, the setup suggestion, and a table of every type's field capacity, wilting point, available water and where its values come from (`basis` in `soil_types.yml`). The Day to day section describes the Map tab.
- [x] **Thin organic surface layers skipped** (Ben, 2026-10-19): Friendship loamy sand was suggested as Muck, because its top horizon in the survey is 2 cm of leaf litter ("moderately decomposed plant material"). The surface texture is now the top horizon only for organic soils (Histosols: Markey, Seelyeville), and otherwise the first mineral horizon (`SURFACE_TEXTURE` in `lib/soils.ts`). Checked against Soil Data Access in Portage and Waushara counties: Friendship, Plainfield, Roscommon and Newson come out as their mineral textures, and the Histosols stay Muck. Minocqua muck (3 cm of muck over silt loam) now suggests Silt Loam.
- [~] *Maybe:* show the survey's available water capacity next to the soil type's default field capacity and wilting point, as a check. Not used in the balance. *(Moved to After launch.)*

## Field boundaries (optional) (was Phase 8 G.10)

A field can have an outline: drawn on the map, imported from a file, or none (as now). It is for the map and the suggested acreage only; the balance and weather don't use it.

**Plan agreed (Ben, 2026-11-12):** the existing `fields.boundary` column (nullable, no default, unused until now), checked by `FieldBoundary`: Polygon or MultiPolygon, closed rings, **at most 1,000 vertices** (100 since G.14 part 7), inside `Pivot::LATITUDES`/`LONGITUDES`, 0.01 to **1,500 acres** (over two sections); mirrored in `lib/geo.ts`, with a spherical polygon area in both (no Turf). The outline's acres are offered for the field's area ("Use 38.2 ac from the outline"), saved through `Field#update` so only open seasons follow. Pages: a full-page **field outline page** (`/fields/:id/outline`: "Same as the irrigation system" for a pivot or linear, drawing with terra-draw, one file's import, acres, the survey's dominant soil, Remove, and **plot pins**: pick a plot, click the map), and **Import field outlines** from Setup (shapefile zip, GeoJSON, KML/KMZ parsed in the browser; a row per shape: its name from a chosen attribute, acres, an existing field (matched by name), New field or Skip, and its system, suggested as the one whose outline holds the shape's center or else the nearest point kind within half a mile; new fields get the outline's acres and dominant soil; one transactional save). Map: a click in a field selects its system and highlights the field (no field panel); a system's marker keeps the badges of its fields without outlines and drops when all have one; outlined fields are named inside at closer zooms. Problems list on Setup only (a quarter mile for point kinds). Splitting a pivot's circle along a line comes later. Demo: a few generated outlines now; Ben tidies the demo farm later and its outlines are copied into the seed then. Libraries: terra-draw 1.39 + terra-draw-maplibre-gl-adapter 1.5 (MIT), shpjs 6.2 (MIT, with proj4), @tmcw/togeojson 7.1 (BSD-2-Clause), all loaded on demand.

- [x] **Storage:** `fields.boundary` (GeoJSON Polygon or MultiPolygon, WGS84, jsonb). Validated on the server: closed rings, at most a few thousand vertices (simplified on import), inside `Pivot::LATITUDES`/`LONGITUDES`, and no larger than a plausible field. Changing it never changes a past season (G.9: acreage for the balance lives on the planting).
- [x] **Import first, drawing second:** most growers already have boundaries (FSA Common Land Unit shapefiles, John Deere Operations Center or Climate FieldView exports, Google Earth). "Import field outlines" in Setup takes a zipped shapefile (`.shp`, `.dbf`, `.prj`; read in the browser with shpjs, which reprojects with the `.prj`), GeoJSON or KML, all parsed in the browser (nothing uploaded but the result). It shows the shapes on the map with their attribute names, lets the grower match each to an existing field or create a field under a chosen irrigation system, previews acres, then saves.
- [x] **Drawing:** terra-draw (MIT, works with MapLibre) for a free-form polygon (click vertices, drag, delete a vertex), loaded on demand like MapLibre. Shortcuts: "Same as the irrigation system" (a field filling its pivot or a linear's rectangle, one click); splitting a pivot's circle along a line for a two-crop pivot can follow.
- [x] **Suggested area and soil:** the outline's acres (`shapeAcres`) are offered for the field's area; the soil suggestion takes the dominant soil in the outline (area-weighted from the soil survey) rather than the soil at a point.
- [x] **Map:** fields with an outline are filled by status (the status colors, validated for color blindness, light and dark); fields without one keep the pivot badges. Irrigation systems are drawn as outlines on top, with a toggle in the layer menu ("Irrigation systems"); a click inside a field selects the field, a click on a system's outline (a wider invisible hit line) selects the system. G.11's partial plantings show as pins in their field.
- [x] **Problems list** (Ben, 2026-11-11): an irrigation system doesn't move with its field (moving it would change the weather cell), so Setup lists fields whose outline is far from, or not under, their system's point or shape ("Home North's outline is 2.1 mi from Traveler: Lane 3"), to fix by hand.
- [x] Tests: GeoJSON validation specs, the import parser on fixture files (a shapefile zip, GeoJSON, KML), `geo.ts` area vitests, the import and draw flows in a smoke test, axe on both.

**Built (2026-11-12)**, as agreed above, with these details:
- **Storage:** `FieldBoundary` (normalizes a JSON string, rounds to 7 digits and drops altitudes; `errors` worded the same in `boundaryErrors`), check constraint `fields_boundary_object`, `Field#boundary_acres`; the spherical area is Turf's formula in both languages (`spec/services/field_boundary_spec.rb` and `lib/boundary.test.ts` assert the same areas). Not checked: self-intersection (terra-draw refuses it while drawing; files are trusted).
- **Outline page** (`FieldOutlinesController`, `Fields/Outline`, `lib/outlines/OutlineMap.svelte`): "Same as the pivot/linear", Draw (corners, then the first again or Enter; finished parts are edited by dragging corners and midpoints, right-click removes a corner), Add a part, Delete the selected part, Import from a file (a file of several shapes asks which), Remove; the tools wait for the map. An outline with holes (from a file) is shown but only replaced, not edited. Area offered with a checkbox (ticked when the field has none), soil with "Use {soil}"; plots this season and ahead pinned by a click (the map scrolls into view) or dragged. One save in a transaction; back to Setup or the field page (`?from=setup`). Linked from Setup's field rows ("Add outline"/"Outline") and the field header.
- **Import** (`OutlineImportsController`, `Setup/ImportOutlines`, `lib/outlines/read.ts`, `matching.ts`, `ImportMap.svelte`): a .shp alone, or a zip without a .prj, is refused with what to do; shapes over 100 corners (1,000 until G.14 part 7) are simplified (Douglas–Peucker, tolerance doubled from 0.25 m); points and lines are counted and left out. Each shape: its field by name (case and spacing ignored; a repeated name by the suggested system), else New field under the system holding its center or the nearest point kind within half a mile, else Skip. New fields get the outline's acres and the survey's main soil (one survey request at a time); existing fields' areas only with "Set existing fields' area from their outlines". Errors keyed `rows.N.attribute`.
- **Map:** `fields-fill`/`fields-line`/`fields-label` under the systems (overlays now go under the fields), `pins`/`pins-label` on top from zoom 14; a system with outlined fields has no fill. The layer menu's "Irrigation systems" switch is `prefs.systems`.
- **Problems** (`lib/outlines/problems.ts`): overlap is a corner inside or an edge crossing; distances to the nearest edge, in mi/ft or km/m.
- **Demo:** generated outlines for North potatoes and North corn (North 160's halves), Hay north, Tomatoes, Arlington 525 (its plots pinned) and both traveler fields; the rest have none, so the map shows both.
- Also: shpjs has no types (`types/vendor.d.ts`); with terra-draw's adapter the `geojson` types resolve, so the drought layer's data is cast where MapLibre takes it; form lists use indexed names (`indexed_list`).

**Considerations carried from the handoff** (2026-11-11):
- **Content Security Policy:** terra-draw, shpjs and togeojson are npm packages bundled by Vite and loaded on demand (`import()`, like MapLibre), never from a CDN. Files are parsed in the browser; only the resulting shape goes to the server.
- **Seasons keep their values:** an outline's acres are offered for the field's area, never copied, and an outline change goes through the field's update like any other, moving open plantings only.
- **A system never moves with its field** (that would change the weather cell); a field far from its system is flagged, to fix by hand. "Same as the irrigation system" exists only for a pivot or linear, which have a shape.
- **Accessibility:** drawing needs a pointer, so the alternatives are importing a file or copying the system's shape.

**Lessons from G.10 and G.14** (from their handoffs):
- MapLibre's `queryRenderedFeatures` returns the top-most feature whatever order its `layers` option lists, and a fill at opacity 0 is still hit; query layers in priority order (`systemHit`).
- A zoom-dependent symbol size is computed per tile and jumps as tiles load: fixed pixel sizes, switched by `minzoom`/`maxzoom`. Images added with `addImage` don't survive a basemap switch, so re-add them (`hasImage` first).
- A color the map or a chart reads from JavaScript goes in the `@theme static` block, read through `readPalette()`, and is validated for color blindness in light and dark, as the chart tokens were.
- Playwright matches role names by substring ("Move its pin" also matched "Remove its pin"): use `exact: true` where one name contains another.
- Don't run Prettier on this file: it reformats every table (lint-staged leaves Markdown alone).
